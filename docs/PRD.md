## 1. 产品目标与定位

### 1.1 产品定位

一款**本地优先、双端可用（Web + 桌面）**的 PDF 编辑器，覆盖「编辑、转换」两类高频场景，让用户无需上传文件到服务器即可完成 PDF 的编辑与格式转换，兼顾隐私安全与操作效率。

### 1.2 产品目标（三个正交目标）

- **G1 隐私安全**：所有文件处理在本地完成，不经过任何服务器，用户文件零上传、零留存。
- **G2 功能完整**：一次性覆盖「PDF 编辑、PDF 转图片、图片转 PDF」三大核心场景，开箱即用，无需安装多款工具。
- **G3 体验专业**：极简专业 UI、响应式布局、清晰的进度反馈与错误提示，降低学习成本。

### 1.3 成功标准（建议指标）

- 首次打开到完成一次「PDF 转图片」的操作用时 ≤ 2 分钟（含理解界面）。
- 三大核心功能的单文件处理全程**无网络请求**（DevTools Network 面板无外部请求，桌面端可断网使用）。
- 核心操作（撤销/重做、页面重排、批量转换）的错误率 < 1%。

## 3. 用户故事

### 核心功能一：PDF 在线编辑

- **US1**：作为设计师，我希望对 PDF 中的文本进行编辑、高亮和批注，以便直接在设计稿评审中标记意见，无需重新导出。
- **US2**：作为办公用户，我希望插入/删除/重排 PDF 页面，以便整理合同或提取需要的章节。
- **US3**：作为文档处理者，我希望在 PDF 上添加图片、形状和签名，以便快速补齐签署或补充说明内容。
- **US4**：作为任何用户，我希望编辑时支持撤销/重做并实时预览，以便放心操作、随时回退。

### 核心功能二：PDF 转图片

- **US5**：作为汇报人，我希望把 PDF 页面转成高分辨率 PNG/JPG，以便放入 PPT 或发送给他人。
- **US6**：作为批量处理者，我希望一键把全部页面转为图片并打包下载，以便节省逐页操作时间。
- **US7**：作为普通用户，我希望转换前自定义 DPI、分辨率和尺寸，以便输出符合印刷或屏幕要求。

### 核心功能三：图片转 PDF

- **US8**：作为办公用户，我希望把多张图片（PNG/JPG/GIF/BMP）合并为一个 PDF，以便生成扫描件合集或电子相册。
- **US9**：作为整理者，我希望转换前调整图片顺序、页面尺寸、边距和缩放比例，以便输出版式统一、整洁的文档。
- **US10**：作为新手用户，我希望转换过程有进度提示和错误说明，以便了解进度并在失败时知道如何修复。

## 5. 功能边界

### 5.1 Web 端 vs 桌面端差异化

| 维度 | Web 端 | 桌面端（Electron/Tauri 候选） |
| --- | --- | --- |
| 文件处理 | 浏览器本地（IndexedDB/File API），资源打包进站点，无服务端依赖 | 本地文件系统直接读写，可保存回原路径 |
| 大文件能力 | 受浏览器内存限制，>100MB 提示性能风险 | 更优，可处理更大文件 |
| 拖拽体验 | 浏览器内拖拽 | 支持系统级拖拽（从资源管理器直接拖入） |
| 离线能力 | 需首次加载完成（PWA 可缓存） | 完全离线 |
| 系统集成 | 无 | 右键「用 PDF 编辑器打开」、文件关联、系统通知 |
| 更新分发 | 静默更新 | 应用更新机制 |

**双端共同点**：三大核心功能、UI/交互逻辑、本地处理内核保持一致，核心代码共享（同一渲染层与处理库），仅外壳与文件接入方式不同。

### 5.2 本地处理约束（必须遵守）

- **零上传**：文件内容不得上传至任何服务器；所有解析、渲染、编辑、转换均在本机完成。
- **无埋点数据外泄**：不采集、不传输文件内容、文件名（除非用户显式同意用于崩溃诊断）。
- **Web 端资源本地化**：核心处理库（PDF 解析/渲染/图像处理）须随应用打包（如通过 Vite 静态资源引入），不得运行时从 CDN 拉取，以保证离线与隐私。
- **数据处理结束即清理**：临时文件/内存中的文件数据在会话结束或关闭文件后及时释放。
- **技术选型约束**：优先选用可在浏览器本地运行的库（如 PDF.js、jsPDF、html2canvas 等社区方案），桌面端可复用同一内核。

## 6. 交互流程概述

### 6.1 主流程

```
打开应用 → 首页（三大功能入口卡片）→ 选择功能 → 加载/上传文件（显示进度）
→ 工作区操作（编辑/转换设置）→ 实时预览 → 导出/保存 → 完成提示
```

### 6.2 PDF 在线编辑流程

1. 首页选择「编辑 PDF」→ 拖拽/选择本地 PDF。
2. 加载完成进入编辑工作区：左侧页面缩略图栏 + 中央编辑画布 + 顶部工具栏。
3. 工具栏切换模式：选择/文本编辑/批注/高亮/插入图片/形状/签名/页面管理。
4. 所有操作即时反映在画布（实时预览），可随时撤销/重做。
5. 点击「保存/导出」→ 本地生成新 PDF → 下载/保存。

### 6.3 PDF 转图片流程

1. 首页选择「PDF 转图片」→ 加载 PDF。
2. 右侧设置面板：格式（PNG/JPG）、DPI、分辨率/尺寸、页范围（默认全部）。
3. 点击「开始转换」→ 顶部进度条 + 每页状态（成功/失败可重试）。
4. 转换完成 → 网格预览 → 单张下载或「打包下载全部（ZIP）」。

### 6.4 图片转 PDF 流程

1. 首页选择「图片转 PDF」→ 多选/拖拽上传多张图片（显示每张缩略图与加载状态）。
2. 列表操作：拖拽排序、删除、旋转。
3. 设置面板：页面尺寸预设/自定义、页边距、缩放比例。
4. 点击「生成 PDF」→ 进度提示 → 预览生成结果 → 下载。

### 6.5 通用交互规范

- 所有耗时操作（>500ms）必须有进度反馈；失败必须有明确错误原因与重试入口。
- 空状态、加载状态、错误状态、完成状态均有对应视觉反馈与文案。
- 移动端：工具栏收起为底部操作栏/浮动按钮，支持触控绘制签名。

## 8. 验收标准

### 8.1 PDF 在线编辑（P0 验收）

- **AC-E1**：可加载本地 PDF 并多页浏览，页面缩略图正确显示。
- **AC-E2**：可选中并修改文本内容，修改后画布即时更新，导出 PDF 包含修改结果。
- **AC-E3**：可添加文字批注与多色高亮，导出后批注/高亮保留。
- **AC-E4**：可插入、删除、拖拽重排页面，导出后页序与内容正确。
- **AC-E5**：可插入图片、形状（矩形/椭圆/箭头/线条）与签名（绘制或图片），导出后元素位置/大小正确。
- **AC-E6**：撤销/重做可正确回退/重放最近操作序列（至少 20 步）。
- **AC-E7**：编辑过程为实时预览，无「保存后才能看到效果」的割裂感。
- **AC-E8**：保存导出的 PDF 可被主流阅读器（Adobe/浏览器/福昕等）正常打开，内容与预览一致。

### 8.2 PDF 转图片（P0 验收）

- **AC-C1**：可将单页或全部页面转为 PNG、JPG，图片可正常打开。
- **AC-C2**：可自定义 DPI（如 72/150/300）、分辨率与尺寸，导出图片符合设定值（允许 ±2% 误差）。
- **AC-C3**：转换后提供缩略图预览，可单张下载。
- **AC-C4**：全部页面转换后可打包为 ZIP 一次性下载，包内图片数量与页数一致、命名有序。
- **AC-C5**：转换过程显示进度，可中途取消；失败页面有明确提示并可单独重试。
- **AC-C6**：100 页以内常规文档转换成功率 ≥ 99%（本地环境）。

### 8.3 图片转 PDF（P0 验收）

- **AC-I1**：可上传 PNG/JPG/GIF/BMP 图片，支持多选与拖拽，加载状态可见。
- **AC-I2**：多张图片合并生成单个 PDF，页数与图片数一致，顺序与列表一致。
- **AC-I3**：可拖拽调整图片顺序，调整后生成顺序随之变化。
- **AC-I4**：可设置页面尺寸（含 A4/Letter 预设与自定义）、页边距、缩放比例，生成 PDF 版式符合设定。
- **AC-I5**：生成过程有进度提示；不支持的格式/损坏文件给出明确错误且不影响其他图片。
- **AC-I6**：生成的 PDF 可正常打开，每页内容完整、方向正确。

### 8.4 通用验收

- **AC-G1**：Web 端与桌面端在 375px（手机）、768px（平板）、1280px+（桌面）宽度下布局正确、可操作。
- **AC-G2**：全流程（加载→操作→导出）在 DevTools Network 面板中无任何外部请求（除本地资源外）。
- **AC-G3**：桌面端断网状态下三大功能均可完整使用。
- **AC-G4**：所有错误场景有明确文案与恢复路径（重试/返回）。
- **AC-G5**：提供内置新手引导与帮助文档，覆盖三大功能的使用说明。

## 9. 附录：默认技术约束（供架构师参考）

- 前端框架：Vite + React + MUI + Tailwind CSS。
- 本地 PDF 处理候选库：PDF.js（渲染/解析）、jsPDF 或 pdf-lib（生成/编辑）、FileSaver.js（下载）、JSZip（ZIP 打包）。
- 桌面端外壳：Electron 或 Tauri（待 Q1 确认），复用 Web 端渲染层与处理内核。
- 所有依赖须可本地打包，禁止运行时 CDN 依赖。
